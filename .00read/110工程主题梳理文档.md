# GEOFlow 工程主题梳理

> 本文按当前仓库代码（分支 `v3.1.0_zh`）整理，用于快速建立工程地图。路径均相对于仓库根目录。

## 1. 工程定位与总体框架

GEOFlow 是面向企业网站的 GEO（Generative Engine Optimization）内容运营平台，核心目标是把“可信知识 → 内容生产 → AI 质量门禁 → 人工审核/发布 → 多渠道分发 → 访问与 AI 可见性反馈”串成可审计的闭环。

技术上采用 Laravel 单体应用，按 Web、API、队列任务和 CLI 复用同一套领域模型与服务：

- **后端**：PHP 8.3、Laravel 12、Eloquent ORM、Laravel Sanctum（API Token）、Horizon（队列监控）、Reverb（实时广播）、Laravel AI。
- **前端**：Blade 模板为主，Vite 构建；Tailwind CSS 4、原生/模块化 JavaScript、Laravel Echo；后台为 Admin UI V3，前台支持可安装主题。
- **数据与异步**：数据库迁移覆盖内容、知识、AI、分发、托管站点、分析、更新器等领域；长耗时工作通过 Jobs/Queue 执行，并用定时调度做恢复、对账与清理。
- **交付形态**：同一应用提供公开内容站、管理员后台、`/api/v1` API、`bin/geoflow` CLI、浏览器运营助手协议和可选托管多站点。
- **治理边界**：中间件统一处理站点解析、管理员认证、API scope、超级管理员、审计日志、当前站点隔离及 AI 工作台错误协议；高风险操作保留预览、授权、回执和审计链路。

主启动与构建入口：

| 入口 | 作用 |
|---|---|
| `bootstrap/app.php` | Laravel 应用组装、路由注册、中间件别名、异常与 API JSON 信封 |
| `artisan` / `routes/console.php` | Artisan 命令与计划任务 |
| `routes/web.php` | 前台站点和管理员后台路由 |
| `routes/api.php` | `/api/v1` 认证 API、任务/素材/文章/浏览器操作 |
| `routes/channels.php` | 广播频道授权 |
| `vite.config.js`、`resources/js`、`resources/css` | 前端开发与生产构建 |
| `composer.json`、`package.json` | PHP/Node 依赖、安装、开发、测试、构建脚本 |

## 3. `app/` 代码分层

```text
app/
├─ Ai/                  AI Agent 与 AI Workspace 编排
├─ Console/             Artisan Commands；GeoFlowCli 子目录实现 CLI 内核
├─ Contracts/           管理、AI Workspace、Outbound、SystemUpdater 等接口
├─ Data/                DTO/数据对象（Admin、Ai、AiWorkspace、Api）
├─ Events/              领域/后台事件，用于广播与异步通知
├─ Exceptions/          API 与领域异常
├─ Http/
│  ├─ Controllers/      前台、后台、API、浏览器操作控制器
│  ├─ Middleware/       认证、站点解析、权限、审计、限流、错误渲染
│  └─ Requests/         表单/接口输入校验与授权
├─ Jobs/                内容、AI 质检/优化、知识、标题、导入、分发、更新队列任务
├─ Models/              Eloquent 领域模型
├─ Policies/            授权策略
├─ Providers/           服务提供者（含 Horizon）
├─ Services/            领域应用服务，按 Admin、AiWorkspace、Api、GeoFlow、Site、Outbound 等分组
├─ Support/             跨模块支撑：GeoFlow、Site、Analytics、Lead、Admin 等
└─ View/Composers/      Blade 视图数据组合
```

### 关键边界说明

- **Controller/Request** 负责协议适配与输入边界；实际业务编排下沉到 `Services`、`Support` 和 `Jobs`。
- **Models + migrations** 形成持久化领域核心；复杂长流程通常用状态字段、运行记录、attempt/lease、审计事件实现可恢复性。
- **Jobs + Commands + Schedule** 构成异步执行面：队列处理耗时操作，命令提供运维/批处理入口，计划任务负责扫描、恢复、对账、快照与清理。
- **Middleware** 是多租户/多表面（public site、admin、API、hosted site）的第一道隔离层；`ResolveCurrentSite`、`EnforceCurrentSiteSurface` 等保证当前主机与站点上下文一致。

## 4. 功能模块地图

### 4.1 内容与知识生产

- **内容资产**：文章、分类、作者、关键词库、标题库、图片库、提示词、敏感词。
- **知识库**：系统/企业知识库、版本、来源、媒体、事实库、证据、知识切片与 embedding；支持向量召回和无向量时的稳定回退。
- **导入与生成**：URL 导入、企业知识草稿、标题批量 AI 生成、任务化内容生产。
- 主要代码：`app/Models` 中 `Article`、`Knowledge*`、`Title*`、`UrlImport*`，以及 `app/Services/GeoFlow`、`app/Jobs` 对应任务。

### 4.2 AI 质量门禁与优化

- 对文章执行证据、数据/引文、广告规则、发布语境等检查，持久化分项评分、证据、建议、版本和审计记录。
- 质量状态会影响发布：待复核、阻断、异常或过期内容停留在草稿/审核链路；支持人工 override、重检、候选优化、应用、取消和回滚。
- 关键模型/任务：`ArticleAiQualityCheck`、`ArticleAiOptimizationRun`、`AiQualityAuditEvent`；关键 Job 为 `ProcessArticleAiQualityJob`、`ProcessAiWorkspaceRunJob`、`ProcessArticleAiOptimizationJob`。

### 4.3 管理后台与运营协作

- Admin UI V3：仪表盘、账户、任务、文章、素材、知识、AI 工作台、分析、分发、系统更新、帮助与多语言。
- 审核运营：文章审核/发布/回收站/批量操作、Markdown 导出、人工发布工作台；保存身份、账号、计划、风险、回执和转换审计。
- 认证与治理：管理员会话、超级管理员、最近页面、活动日志、API Token/scopes、幂等键、敏感操作限流。

### 4.4 AI 工作台与模型治理

- 对话、消息、计划、步骤、运行、审批、工件、外部操作、trace 和 surface events。
- 管理 AI 模型与来源提供商、共享/个人配置、用量事件、执行身份、失败回退和可观测性。
- 代码集中在 `app/Ai`、`app/Services/AiWorkspace`、`app/Data/AiWorkspace`、`app/Models/Ai*` 及后台 AI 路由。

### 4.5 多站点、主题与前台内容站

- 默认公开站：首页、关于、分类、文章、归档、站点发现（robots/sitemap/llms 等）、线索表单与提交。
- 主题系统：`resources/views/theme` 下按主题目录提供 `manifest.json`、layout、home、category、article、partials、assets；`SiteThemeCatalog`、`SiteThemeViewResolver` 等负责解析和渲染。
- 托管站点：子域名分配、生命周期（预检/激活/暂停/维护/归档）、文章分配、配额、缓存失效、索引观察和状态对账。

### 4.6 分发渠道与人工发布

- 渠道类型覆盖 GEOFlow Agent、托管站点、WordPress REST、通用 HTTP 等；支持密钥轮换、健康检查、能力刷新、配置同步、任务重试与失败冷却。
- 浏览器运营协议通过设备配对和最小权限 Token 领取人工发布工单、回传执行凭证，最终发布由运营人员确认。
- 主要模型：`DistributionChannel`、`ArticleDistribution`、`DistributionLog`、`ManualPublication*`、`HostedSite*`；主要路由位于 `routes/web.php` 和 `routes/api.php`。

### 4.7 分析、AI 可见性与线索

- 访问日志记录 PV、路径、站点和爬虫分类；后台提供内容、流量、线索、分发和 AI 可见性分析。
- AI 可见性支持关键词采集、来源、竞品发现与运行记录。
- 线索模块包含表单管理、公开提交、后台查看/编辑/导出。

### 4.8 系统更新、部署与运维

- `SystemUpdater` 负责签名更新、完整备份、环境验收、恢复点回滚；高风险操作要求管理员密码与验证器授权码。
- Horizon 监控队列；Reverb 提供实时广播；Docker、deployment、deploy-scripts 支持不同部署场景。
- 命令与计划任务还负责队列恢复、AI 运行对账、知识同步恢复、托管站点 reconcile、缓存/导出/审计数据清理。

## 5. 路由与运行面

| 运行面 | 文件/前缀 | 主要职责 |
|---|---|---|
| 公开站点 | `routes/web.php`，站点路由 | 内容展示、SEO/站点发现、线索表单、当前站点解析 |
| 管理后台 | `routes/web.php`，配置的 admin base path（默认 `/geo_admin`） | 管理、审核、AI 工作台、分析、分发、更新 |
| API v1 | `routes/api.php`，`/api/v1` | Token + scope 保护的目录、任务、素材、文章、浏览器运营协议 |
| 广播 | `routes/channels.php` | 管理任务等私有频道授权 |
| CLI | `bin/geoflow`、`app/Console/GeoFlowCli`、Artisan | 自动化、远程操作、运维和批处理 |
| 队列/计划 | `app/Jobs`、`app/Console/Commands`、`routes/console.php` | 异步工作、恢复、对账、快照与清理 |

请求通常经过：主机规范化 → 当前站点解析 → 当前站点表面约束 → 表面专用认证/权限 → 控制器/服务；API 错误统一为带 request id 的 JSON 响应，后台 AI 工作台有专门的 JSON 错误协议。

## 6. 数据与异步主题

- **基础设施表**：users、cache、jobs、failed jobs、personal access tokens。
- **业务域表**：tasks/task runs/schedules、articles/reviews/images、materials、authors/categories/keywords/titles。
- **知识与 AI 表**：knowledge bases/revisions/chunks/facts/evidence、AI models/providers/usage、quality checks/segments/rollouts/audit、workspace runs/steps/traces。
- **交付与站点表**：distribution channels/logs/operations、hosted sites/assignments、theme replication、manual publications。
- **治理与运维表**：admins/activity、view logs、leads、system updates/backups/runs/states、idempotency keys。

异步流程普遍采用“创建运行记录 → 获取 lease/attempt → Job 执行 → 持久化结果/审计 → reconcile/recovery”模式，以支持超时、重试、并发和进程中断后的恢复。

## 7. 开发、测试与维护入口

- PHP 依赖与测试：`composer install`、`composer test`（内部执行 `php artisan test`）。
- 前端构建：`npm run dev`、`npm run build`；JavaScript 测试位于 `tests/JavaScript`。
- 一体化开发：`composer dev` 同时启动 Laravel、队列、AI 质量 worker、优化 worker、Reverb、日志和 Vite。
- 测试分层：`tests/Unit`、`tests/Feature`、`tests/Browser`、`tests/PostgreSQL`、`tests/JavaScript`，并有 `Fixtures`、`Support` 辅助夹具。
- 配置集中在 `.env.example`、`.env.prod.example`、`config/*.php`；不要将真实密钥、Token、客户数据写入仓库。

## 8. 阅读工程的推荐顺序

1. 先看 `README.md`、`composer.json`、`package.json`，确认产品能力和运行依赖。
2. 阅读 `bootstrap/app.php`，理解请求生命周期、中间件和错误边界。
3. 以 `routes/web.php`、`routes/api.php` 建立用户/自动化入口地图。
4. 沿控制器进入 `Services`、`Jobs`、`Models`，再用对应 migrations 核对数据状态机。
5. 前台问题查看 `app/Http/Controllers/Site`、`app/Support/Site` 和 `resources/views/theme`；后台问题查看 `resources/views/admin`、`app/Http/Controllers/Admin` 与 `app/Services/Admin`。
6. AI/异步问题查看 `app/Ai`、`app/Services/AiWorkspace`、`app/Jobs`、`routes/console.php` 和 `config/geoflow.php`。
