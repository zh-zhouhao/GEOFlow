# GEOFlow 修改、构建与发布说明

本文面向 GEOFlow 的开发、测试和生产发布。默认项目目录为：

```bash
/home/zh/Desktop/001work/100GEOFlow/GEOFlow
```

所有命令都应在项目根目录执行。生产环境不要直接使用测试环境的 `.env`、数据库、Redis 数据或密钥。

## 1. 环境和 Compose 文件

| 环境 | 用途 | Compose 文件 | 默认入口 |
| --- | --- | --- | --- |
| 测试/开发 | 编码、联调、功能验收 | `docker-compose.yml` | `http://服务器IP:18080` |
| UI V3 候选测试 | 隔离验收，不污染正式数据 | `docker-compose.yml` + `docker-compose.ui-v3.yml` | `http://服务器IP:28080` |
| 生产 | 对外提供正式服务 | `docker-compose.prod.yml` | 正式域名 |
| 受管生产 | 推荐的蓝绿升级、备份和回滚 | GEOFlow Updater 管理的 Compose | 由 Updater 管理 |

先确认当前 Git 状态，不要覆盖其他人的改动：

```bash
git status --short --branch
git log -1 --oneline
```

## 2. 修改什么文件

| 修改内容 | 主要文件/目录 | 额外动作 |
| --- | --- | --- |
| 控制器、请求校验、授权、后台逻辑 | `app/Http/Controllers/`、`app/Http/Requests/`、`app/Policies/` | PHP 镜像重新构建；补充权限和请求测试 |
| 业务服务、队列、事件 | `app/Services/`、`app/Jobs/`、`app/Events/`、`app/Listeners/` | 重建相关 worker；高风险变更先排空队列 |
| 模型、关系、类型转换 | `app/Models/` | 字段变化必须同时新增 migration |
| 数据库表、索引、数据迁移 | `database/migrations/`；必要时 `database/seeders/` | 测试库验证迁移；生产不能直接改表或自动跑演示 Seeder |
| Web/API/后台路由 | `routes/web.php`、`routes/api.php`、`routes/console.php` | 检查路由列表、认证和权限 |
| Artisan 命令 | `app/Console/Commands/` | 检查 `php artisan <command> --help` |
| 配置默认值 | `config/` | 配置代码进镜像；密钥只写环境文件 |
| Blade 页面、组件、邮件模板 | `resources/views/` | 涉及 Vite 资源时运行 `npm run build` |
| JavaScript、Vue、交互逻辑 | `resources/js/` | 运行 `npm run build` |
| Tailwind/CSS/主题样式 | `resources/css/`、Tailwind/Vite 配置 | 运行 `npm run build`并做响应式验收 |
| 图片、字体、静态文件 | `public/` 或对应 `resources/` | 构建生产镜像；不要提交大体积运行数据 |
| 公开主题、渠道包 | `resources/themes/`、对应 `app/Domain/` | 验收 SEO、Schema、sitemap 和空状态 |

以下内容不要直接提交或用源码覆盖：`.env`、`.env.prod`、密钥、`storage/`、数据库卷、上传文件、`vendor/`、`node_modules/` 和生成的 `public/build/`。

## 3. 测试/开发环境

### 3.1 首次启动

```bash
cd /home/zh/Desktop/001work/100GEOFlow/GEOFlow
cp .env.example .env                 # 仅首次执行；已有 .env 不要覆盖
docker compose build
docker compose up -d --remove-orphans
docker compose ps
```

首次启动由 `init` 服务执行迁移和空库安装。前台通常是 `http://服务器IP:18080`，后台通常是 `/geo_admin/login`；实际值以 `.env` 为准。

### 3.2 修改后的构建、重启和测试

```bash
docker compose build                    # PHP、依赖或 Dockerfile 有变化时
npm ci                                   # package-lock.json 变化时才执行
npm run build                            # JS、CSS、Vite 资源变化时
docker compose up -d --remove-orphans
docker compose ps
docker compose exec app php artisan test --compact
docker compose exec app php artisan route:list --except-vendor
```

只改前端并使用本地 Node 开发服务器时可运行 `npm run dev`；提交或部署前仍要运行 `npm run build`。

PHP 文件有修改时：

```bash
docker compose exec app vendor/bin/pint --dirty --format agent
```

### 3.3 UI V3 隔离验收

必须同时使用两个 Compose 文件：

```bash
./scripts/ui-v3-up.sh
docker compose -f docker-compose.yml -f docker-compose.ui-v3.yml ps
docker compose -f docker-compose.yml -f docker-compose.ui-v3.yml stop
```

只有确认不再需要候选数据时才删除卷；该命令会清空候选环境数据：

```bash
docker compose -f docker-compose.yml -f docker-compose.ui-v3.yml down --volumes --remove-orphans
```

## 4. 提交前检查

```bash
git diff --check
docker compose config --quiet
docker compose exec app php artisan test --compact
npm run build
```

确认测试通过后，在功能分支提交。不要把环境文件、日志、数据库导出、`storage/` 或依赖目录提交进去。

## 5. 生产首次部署（空数据库）

首次安装只能用于空数据库；已有数据实例不能使用首次安装脚本升级。

```bash
cp .env.prod.example .env.prod
# 编辑 .env.prod：APP_URL、APP_KEY、DB_*、REDIS_PASSWORD、WEB_PORT、HTTPS/代理配置等

docker compose --env-file .env.prod -f docker-compose.prod.yml build
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d postgres redis
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d init
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --remove-orphans \
  app web queue ai-quality-queue ai-quality-backfill-queue \
  ai-optimization-queue knowledge-queue scheduler reverb
bash deploy-scripts/geoflow-healthcheck.sh
```

也可以使用新服务器首次部署脚本：

```bash
bash deploy-scripts/geoflow-docker-deploy.sh
```

执行前核对脚本目标目录、域名、端口和密码来源。

## 6. 已有数据生产环境的发布

### 6.1 推荐：GEOFlow Updater

受管生产环境不要手工 `git pull`、`composer install`、`npm run build` 或直接执行 `migrate`。先诊断和预演，再执行已核对的签名升级计划：

```bash
sudo geoflow-updater doctor --instance primary --json
sudo geoflow-updater update --instance primary --dry-run --json
sudo geoflow-updater update --instance primary --plan-sha256 <已核对的计划SHA256> --allow-maintenance
sudo geoflow-updater verify --instance primary
sudo geoflow-updater doctor --instance primary --json
```

项目兼容入口：

```bash
sudo ./scripts/geoflow-deploy.sh status --instance primary --json
sudo ./scripts/geoflow-deploy.sh update --instance primary --dry-run --json
sudo ./scripts/geoflow-deploy.sh update --instance primary --plan-sha256 <已核对的计划SHA256> --allow-maintenance
```

Updater 负责备份、镜像/计划校验、停机排空、迁移、切换、验证和恢复记录。只有确认目标计划和检查结果后才执行正式更新。

### 6.2 非受管生产：手动 Compose

先备份 `.env.prod`、`storage/` 和 PostgreSQL 数据，并安排维护窗口。涉及安全迁移、图片路径或在途任务时，严格按 `docs/deployment/DEPLOYMENT.md` 第 3.1 节执行停机、排空、迁移、readiness、安全审计和恢复流量；禁止滚动升级或 migration-first。

普通代码/前端镜像更新的基础命令：

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml build
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --remove-orphans \
  app web queue ai-quality-queue ai-quality-backfill-queue \
  ai-optimization-queue knowledge-queue scheduler reverb
bash deploy-scripts/geoflow-healthcheck.sh
```

修改 `.env.prod` 后必须重新创建使用该配置的容器。PHP 生产镜像通常关闭 OPcache 自动刷新，PHP 代码变更必须重新构建并重建 `app`、`queue`、`scheduler` 等相关服务。

## 7. 发布后验收和回滚

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml ps
bash deploy-scripts/geoflow-healthcheck.sh
```

至少检查前台首页、后台登录、关键 API、队列、Reverb、上传文件、数据库连接、错误日志和 HTTPS 反向代理。发现异常先停止继续发布，不要删除数据卷。

受管生产优先使用应用回滚：

```bash
sudo geoflow-updater recovery-points --instance primary
sudo geoflow-updater switch-back --instance primary --json
```

数据回滚必须明确指定已核对的恢复点，不能把应用回滚当作数据库回滚：

```bash
sudo geoflow-updater rollback --instance primary --recovery-point <恢复点ID>
```
